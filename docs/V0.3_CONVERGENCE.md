# DDC-OS v0.3 Crystalline/Radial convergence

Status: experimental public contract; no new kernel authority.

v0.3 aligns the public DDC-OS boundary with the current eight-dimensional DDC model while preserving the v0.2 shared/delta substrate and public/private separation.

## Eight dimensions

DDC-OS now exposes these public dimensions:

- semantic
- authority
- state
- resource
- security
- physical
- frequency
- lineage

Frequency is observational and non-authoritative. Frequency observations may contribute evidence or profitability analysis, but may not create compute identity, integrity, equivalence, or execution authority.

## Radial boundary

Radial is represented publicly as an evidence-generation fabric. It preserves the lens and evidence identity for each finding and preserves contradiction or unresolved state rather than collapsing disagreement into confidence.

Radial does not authorize execution. Distinct lenses are also not presumed to be independent failure paths.

## Transition boundary

The public v0.3 transition path is:

```text
observation
  -> eight-dimensional snapshot
  -> Radial evidence
  -> dimensional closure
  -> predecessor check
  -> shadow eligibility only
```

A successful public transition decision is `ShadowEligible`, never `Authorized`. Existing DDC admission/authority boundaries remain required before execution.

## Safety invariants

- v0.2 exact compute identities remain byte-compatible.
- Frequency-only change cannot alter the non-frequency boundary identity.
- Radial evidence cannot grant authority.
- Contradictory or unresolved Radial evidence falls back.
- Any changed dimension outside the explicit permitted envelope falls back.
- A stale predecessor falls back.
- No v0.3 convergence primitive writes the kernel or changes scheduler/memory policy.
